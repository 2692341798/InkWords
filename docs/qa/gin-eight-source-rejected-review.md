## 已证实的内容改善和剩余问题

源码段落已正确说明 Gin 的最长公共字节前缀、节点路径分裂及前缀比较，并引用新增
`longestCommonPrefix` 和 `(*node).addRoute` 片段。这消除了原 r6 正文把 Gin 描述为
斜杠分段树的主要错误，但以下问题仍使它不适合直接批准：

1. 结构化 `understanding.mechanism` 仍泛称框架节点按路径分段组织；必须与正文区分
   Gin 压缩树和教学分段树。`tradeoffs` 中“哈希表无法支持通配符”过于绝对。
2. 教学 `findRoute` 调用会创建方法根节点的 `getRoot`；未知方法查询修改了路由结构，
   随后的 root == nil 分支不可达。应将注册时创建与查询时读取分开。
3. GET / POST 测试只检查处理函数非空，不能证明同一路径的方法分别执行不同结果。
   还缺少未登记父路径不命中、后来登记父路径且子路由保持的断言。
4. splitPath 跳过第一个字节，并忽略空段，隐含接受重复/尾部斜杠归一化；需明确输入
   约束、根路径和归一化边界，不能让读者误认为等同 Gin。
5. 渐退练习让读者新增已登记的 /api/health；复述题又在刚添加 POST 后问它为何找不到。
   需按前后程序状态修正问题及答案，避免练习自相矛盾。
6. 先验激活要求“不清楚则先回顾”，但没有给出明确补学路径；整章仍需自学审校。
