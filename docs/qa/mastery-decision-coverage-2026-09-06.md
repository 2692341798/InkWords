# 评分要求覆盖与分数一致性验收

日期：2026-09-06。工程与界面验证通过；代表性真实评分仍未通过，候选未部署。

## 从失败证据到结构约束

上一轮真实流程答案的模型理由承认因果缺失，却给了 3 分。此前合同只校验分数范围、
逐字引文、来源 ID 与运行身份，无法检查明确的“未满足要求”和达标分是否矛盾。
本轮新增 v5 输入策略 inkwords.criterion-coverage.v1；原 v1–v4 输入和请求保持兼容。

模型按每个冻结 rubric 返回一个 decisions 条目，包含 criterion_id、原样 requirement、
status 与显式 gaps。服务端要求完整且不重复覆盖，requirement 必须等于本项 description，
缺口的 requirement_quote 必须逐字来自本项要求：

| 判断 | 分数 | 缺口 |
| --- | --- | --- |
| satisfied | 3–4 | 必须为 [] |
| unsatisfied | 0–2 | 至少一项，包含要求原文和缺口说明 |
| unknown | null | 必须为 []，原因在原评分理由中说明 |

生成、持久化成功结果与读回都检查这些关系。矛盾结果拒绝，不自动改分，不重试模型；
无同一工件运行证据的运行项继续未知。判断本身仍可能错误，结构校验不能证明语义真实。
正分引文与来源/运行校验继续执行，不能让参考答案冒充学习者作答。

原始 decisions 与模型反馈共同保存；用户纠正针对有效反馈，不能重写原判断。真实临时
PostgreSQL 验证将静态项 3 改为 2 后仍保留原 satisfied 判断；应用为 needs_practice，
运行项保持 null，原学习作答不改，未新增模型调用。前端可展开原始模型判断、冻结要求、
缺口和参考答案，明确它们与当前纠正后的评分的关系。

## 本轮真实调用

仍使用已配置的 DeepSeek / deepseek-v4-flash，四份既有合成答案、同一参考答案、题目、
rubric 和三段冻结来源保持。新增决策策略进入输入/请求 hash。先离线预检，四例请求分别
11055 / 10564 / 10224 / 10295 字节，小于 32000；单例输出上限 3000 Token、60 秒超时。
设置 INKWORDS_REAL_ASSESSMENT_DECISION=approved 才在真实验收入口选择 v5 夹具。

| 样本 | 返回与验收 | 输入 / 输出 Token | 延迟 ms |
| --- | --- | --- | --- |
| 完整因果答案 | 五项均 4；五个要求原文与 satisfied 判断完整；本例通过 | 3001 / 1281 | 7314 |
| 正确流程复述 | 输出/证据合同拒绝，有效反馈为空；不是零分 | 2898 / 1341 | 7138 |
| 遗漏、误解答案 | 未调用，因前例失败而停止 | — | — |

共 2 次调用，输入 5899、输出 2622 Token，延迟合计 14452 ms；费用未知。
第二例缓存 Token 512，第一例未报告。没有额外重试、备用模型或合成学习库写入。

自动复核完整答案的因果引文实际表达 GET/POST 隔离理由，逐项判断与要求及评分一致。
第二例只保留了通用拒绝结果和用量，未保留无效模型正文，因此无法确认是新判断约束、
已有引文校验还是输出结构触发拒绝；不能声称已证明因果过评分被识别，也不能将本批
称为语义校准通过。

由此补齐有界拒绝诊断：后续结果保存 response_schema、feedback_contract 或
decision_coverage / decision_requirement / decision_gaps / decision_gap_requirement /
decision_score / decision_status；只有与冻结 rubric 匹配的条目 ID 才进入诊断。
不保存模型正文、作答或供应商错误体。诊断的字段与分数矛盾、题外缺口负例测试通过，
新增诊断后离线请求 hash 与真实调用时逐一相同；本轮未为补诊断重复调用。

同时修复验收产物把未计算得分写成 0 的问题：只有合法反馈完成汇总后才输出 acceptance。
旧的第二例原文件保持原样，其 acceptance 的零值是旧写出器占位，不能当作分数；独立
semantic-review.json 明确标记 acceptance_available=false。
