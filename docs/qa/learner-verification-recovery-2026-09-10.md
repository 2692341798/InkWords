# 学习者验证状态恢复验收

日期：2026-09-10。来源：`delegated_ai` 工程验收。

## 触发问题与修复

PRD 528 要求代码验证任务可取消、可恢复查看，刷新不丢状态。检查实际学习者页面发现：
最新任务读取失败被静默忽略，可能显示“尚未运行”；能力预检使用代码读取的共同超时控制器，
代码提前完成会撤销预检时限；运行器不可用会隐藏已有结果；切换作答保留旧文件状态；启动响应
丢失后再次点击生成新 request_id。轮询还会重叠，并可能以晚到响应覆盖取消结果。

新增 `frontend/src/hooks/useLearnerVerification.ts` 统一管理预检、持久化状态读取和显式动作。
`LearnerCodeSnapshot` 继续负责原文件展示，并以目标/作答/hash 作为组件身份。

- 预检、历史状态、运行状态以及启动/取消响应各有独立 10 秒时限。响应超时只表示未确认，
  不制造服务器任务的失败、取消或完成状态。
- 历史读取尚未成功或失败时不显示“尚未运行”，也不提供新的执行入口。重新读取只执行 GET。
- 当前能力与历史结果分别展示；运行器离线不抹去既有记录，不允许新执行。
- 轮询串行执行，错误显式显示并保留最后已知状态，继续读取原 run ID，不重新运行。
  卸载和取消/启动期间的旧响应不能覆盖当前状态。
- 启动响应未确认时保留原 request_id、input_hash 与 retry_of；“重试启动请求”重发同一请求。
  成功确认后才清除待确认请求。服务端幂等与终态规则不变。
- 预检 snapshot_hash 和历史任务的目标/作答/快照身份不匹配时拒绝展示为可执行结果。
  原文件读取或身份验证失败时不提供启动按钮。
