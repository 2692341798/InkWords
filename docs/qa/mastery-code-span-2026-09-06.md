## 解决的问题

真实诊断捕获到模型将多行 Go 代码压为一行后放入 `answer_quote`，即使明确提示保留
空白仍再次发生。原逐字校验正确拒绝了它。另一个矛盾是：模型将缺少运行记录的条目
判为未知并留空引用，但合同要求它引用无关技术来源才能保存。

新 v6 代码请求采用 `inkwords.numbered-learner-code.v1`，为每个文件的全部物理行编号，
每行保留原始字符、制表符和换行；文件字节只发送一份。模型使用 `answer_path` 与
`answer_span={format: inkwords.code-line-range.v1, start_line, end_line}` 选择单个文件内
首尾均包含的行，代码 `answer_quote` 为空。领域投影从冻结文件提取原文，前端继续
展示代码路径与原文。行号数据及 JSON 包装均进入已有输入预算和请求 hash。

原模型选择保存在 `Result.judgments`，派生引文保存在 `Result.feedback`。成功保存和
读回重新解析、逐字比较；纠正只追加有效反馈，不能改写原判断。错误格式、零/反向/
越界行号、未知文件、没有路径、范围与自写引文同时出现均拒绝。LF、CRLF、无末尾
换行和多文件的字节还原有测试。旧 v1–v5 请求保持，新解析器仍能读取没有范围的旧
v6 逐字引文；文字 v6 请求未变。

仅当 v6 代码条目需要运行证据、当前输入完全没有 runtime 记录且分数为 null 时，
才允许显式空引用数组 `[]`。未知不是零分，也不声称运行成功。静态条目、任何有分数
条目、已提供运行记录和提示建议仍要求有效来源。前端允许只纠正未知项的说明，不能
将其改成数值分数，也无需选择无关来源；数组不返回 null。
