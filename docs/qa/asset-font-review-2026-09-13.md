# 图片内部字体补证：实现与本机验收

2026-09-13。用户委托 AI。合同与回退边界见 [设计记录](../decisions/asset-font-review.md)。

## 已实现行为

权利追加补证支持版本化 `asset_font_review`。保存时绑定该构建的冻结 asset ID、哈希与
图片类型，复用现有 JSONB、前序 CAS、幂等键和审阅来源；原件、母稿和冻结构建不变。
新表单默认尚未核对，明确区分“已识别全部字体”与“已检查无文字/字形”。引用固定字体
文件及当前权利补证版本，保存期间不可编辑，失败重试不更换用户审阅过的绑定。

导出重新解析权利账本，只接受素材最新补证；缺记录、素材 pending、错构建/哈希、
字体缺失/pending/变更版本均阻断。后续补证省略声明会撤下旧声明，不自动继承。
完整 PNG/JPEG 字节经过原渲染器验证；SVG、对象、视频、外部图像等未支持载体继续拒绝。
正文/页脚受限字体来源规则和 PDF/AST/HTML 哈希绑定保持。
有效的图片字体证据只能移除 PDF 字体一项阻断，不能代替作品权利、试学或整书晋级。

## 失败记录与实际限制

首个数据库夹具使用不满足 `input_hash` 约束的占位值，实际数据库拒绝；改为有效摘要并
重新计算该独立夹具 manifest hash 后通过。PDF 正向夹具起初缺 renderer/字体观测详情，
被既有绑定校验拒绝；补齐真实合同所需测试字段后通过，没有放宽生产校验。

全量并发首跑出现临时 PostgreSQL 启动连接重置，以及既有蓝图测试在异步页面渲染前断言。
保留原失败日志，后端以 `go test -p 1 ./...`、前端 `npm test -- --maxWorkers=2` 重核全部
通过；没有修改这两个无关模块来隐藏失败。个别路径搜索和辅助脚本 cwd 错误未修改产品数据。

功能和正向夹具不证明当前三张 VS Code 图的实际字体来源已经齐备。现有八条审阅中的
rights v1 是本次实现前的历史记录；其“合同不覆盖”工程缺口已解决，真实文件来源和
权利补证仍缺，故没有伪造 ready 或新字体声明。下一步核对每张图的完整字体来源与实际
许可范围，再登记对应文件的构建权利并通过真实表单追加证据；无法识别就保留阻断。
hands_on 章、读者试学、个人六维学习和原综合验收仍未完成。
