## 配置与工程修改

此前 DeepSeekGenerationAdapter 对全部 provider-neutral 请求使用
LightweightChatOptions，固定关闭推理。新增 Request.ReasoningEffort 可显式选择
low/high；空值保持旧行为，非法值或无明确输出预算在联网前失败。
[DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)
确认 low/high 可配置，思考开关与 effort 为独立参数；核对日期 2026-09-06。

评分通过 NewGeneratorWithOptions 注入任务设置，仅对 v6 canonical judgments 生效。
设置进入完整请求序列化、RequestHash、Preview 和 Result；不改变原 InputHash。
旧构造函数、生产 bootstrap、历史 v1–v5 请求与未显式启用的 v6 保持原样。
本次对比原预检的 8 份 v5/v6 请求哈希，全部保持。

DeepSeek 的 JSON 与流式路径均映射显式参数，实际本地 HTTP 服务捕获验证。
OpenAI 适配器尚未配置该选项，遇到非空值会在联网前拒绝，避免静默忽略。
这不表示 OpenAI 模型本身不支持推理，只是当前适配器未实现对应配置。

无效 JSON 或缺少最终内容时，已返回的 DeepSeek 用量仍保留，失败结果不保留正文。
推理文本不进入最终输出或流事件。没有新增依赖、迁移、索引或远端变更。

low 失败后补充 AssessmentFeedbackError 的稳定规则码：区分缺少段落、条目异常、
作答引文、运行依据、反馈数量/文本、证据数量/身份。已知 rubric 条目可附冻结 ID，
模型自造 ID、引文和来源正文不进入诊断。既有错误文字和拒绝条件保持。
这项诊断只适用于之后的调用，本轮没有为取得新原因码再次调用。
