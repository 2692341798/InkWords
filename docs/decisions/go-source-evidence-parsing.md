# Go 源码声明定位与解析版本

2026-09-06。真实 Gin 源码导入暴露了三个断点：空行切片无法保留函数机制与 Symbol；
样章适配器丢弃六个固定符号之外的已选证据；检索出的列表外片段不能进入蓝图选择。

## 解析与冻结身份

Go 文件改用标准库 go/parser 和 go/ast 读取声明，不加载依赖、不类型检查、不执行
init 或任何源码。完整函数/方法包含文档注释及内部空行；package、import、类型声明及
其他文本仍保留。方法记录规范化接收者符号，例如 `(*RouterGroup).GET`；泛型接收者
记录基类型。字节范围和行号按冻结文件的物理位置计算，忽略 `//line` 的虚拟路径/行号。
Go 语法不完整时拒绝提供看似完整的声明定位；这不代表语法通过的代码可以编译或运行。

新资料导入任务为 v3，InputHash 纳入 parser_version。原始 SourceSnapshot 的文件哈希
和上游 commit 不变，但显式重新导入会创建新的解析快照与文档/片段 ID；相同 v3 输入
仍由任务幂等键去重，worker 重试复用冻结 SnapshotID。v2 任务继续按空行解析并保留
既有按源/commit/文件哈希的持久化行为。新任务按 SnapshotID/source_id 查找，禁止把
新符号结果静默替换为旧空行结果；保存后的 status、文件 hash、commit 必须一致。

新查询使用既有索引，没有新增索引、schema 或数据迁移。真实 PostgreSQL 回归覆盖
旧快照保留、新快照追加、重复结果不增加记录及 Symbol 入库，并保存 EXPLAIN 证据。
解析快照在 limits_json 中记录 parser_version 供审计；它不作为查询索引键。

## 检索和样章

检索新增可解释的“源码符号”匹配权重，使函数声明优先于只提到函数名的调用位置。
检索 API 候选新增 locator（含原始 path/symbol/start_line/end_line）；旧记录没有此项
时仍可读取。蓝图的显式勾选列表合并有界检索候选，不自动选中；已保存但超出初始列表
的 ID 可见且可移除，未加载到的定位不会被编造。源码证据仍需由作者选择和批准。

刷新恢复时，`GET /api/v1/textbook-projects/{projectID}/source-evidence` 支持重复的
`chunk_id` 查询参数，单次最多 200 项，每个 ID 非空且不超过 200 字节；省略参数仍返回
原先的首批 200 项。响应增加原始 locator，不含 SearchText 或源码正文。补查仍通过
workspace / project / 未删除资料的关联查询，缺失或不属于项目的 ID 不返回，不能改为
模糊匹配。前端从已保存蓝图提取并去重 ID，仅补查首批缺少的项，按 200 项和约 6000
编码字符的较小边界分批。未返回的项继续显示 ID 占位，不自动勾选新证据。
查询使用现有 source_chunks / source_documents / source_snapshots / textbook_sources
主键；无新增索引、写放大或迁移，额外成本是打开工作台时针对已选项的元数据读取。
新后端应先于新前端更新；回退前端仅恢复 ID 占位，不修改已保存蓝图。

Gin 首章仍保留六个生命周期锚点的兼容别名；其他已选证据以稳定 source-ChunkID 别名
进入请求、引用映射和关键事实，不再丢弃。重复的必需锚点仍失败，官方补充同名符号
不会冒充主资料锚点。这里没有扩大为全书通用生成器，也没有自动修改旧批准蓝图。

## 回退及验收边界

保留旧快照、当前原始资料卷和 v3 任务即可回退代码；旧应用不认识 v3 时应保留任务
并停用新导入，不能将其改写成 v2 重试。无需删除或恢复数据库。已经冻结的母稿、
来源、人工审阅和运行证据不因解析升级而自动迁移。

解析/检索/引用合同通过不等于源码讲解正确，也不等于教材代码运行通过。真实文件
重解析后仍须对照原字节检查 Symbol 位置，明确选择足够且不过量的证据，再审阅新
蓝图和候选内容。当前 retrieval 候选扫描上限 500、初始选择列表上限 200；更大资料库
尚需单独完成分页/检索扩展，不能把此次 Gin 范围的验证当作任意规模支持。
