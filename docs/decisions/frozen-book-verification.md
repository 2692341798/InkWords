# 冻结构建同时固定运行验证收据

日期：2026-09-10。

## 问题与行为

原 BookBuild 只固定代码 ID、修订、代码树与清单哈希，审校 ZIP 的 `verification-summary.json` 恒为 unavailable；运行预检还查询后来的数据库收据。这会让冻结后运行成功的测试改变旧构建的技术检查结论，并使离线审阅者拿不到观察结果。

新建构建使用 `inkwords.book-build-input.v2`，外层 `inkwords.book-build.v1` 与 Canonical Book AST 保持兼容，增加 `verification_snapshot`（`inkwords.book-verification-snapshot.v1`）。core-api 在工作区项目锁定的构建事务内，按已批准修订及其候选来源收集代码清单和现存收据；不接受客户端提供运行输出，也不执行代码。

快照固定合同哈希、采集时刻，以及每个工件的 ID、来源修订、代码树哈希、清单哈希、完整结构化清单和运行收据。收据保留输入哈希、命令清单、工具链、运行器摘要、观察输出、采样条件、时间、到期日、原始证据引用及截断标记。不存在收据时保留空数组，不造成功结果。

## 判断与版本边界

共享纯合同负责快照校验、与外层工件列表的逐项绑定和日期判断。每个声明命令都需要有效收据；核对来源修订、代码树、清单哈希、按运行器计算的输入哈希、合同、工具版本和到期时间。终端成功还要求确切的命令模板、成功状态和 exit_code=0。浏览器收据沿用既有结构化捕获合同，要求本地页面路径及已观测的文本断言匹配对应命令，且截图引用、控制台、网络与工具版本齐全。终端或图片记录不能代替浏览器证据。

导出的 `inkwords.book-verification-summary.v1` 包含构建 ID、manifest 哈希、原始快照、`at_freeze` 与 `at_export` 两个日期明确的判断。到期后历史观察保持，但当前判断不再通过。失败、不匹配、未覆盖和过期原因可检查；无工件的空集合只表示没有声明的工件命令，不声称实际运行过任何程序。

core-api 与 export-service 对含快照的新构建均只使用冻结收据进行代码预检。后来的收据不能修复旧快照；用户需要显式重新冻结，产生新的待审构建并重新审阅。收据内容进入幂等输入哈希，冻结时钟不进入，避免重复点击制造重复构建或延长证据寿命。

旧构建不回填、不改哈希，导出仍明确 unavailable，旧版预检兼容行为保留。声明快照版本却缺字段、未知格式、null 快照、重复或遗漏工件不能静默退回旧版。已批准母稿和旧审阅记录均不改写，新构建没有自动继承审阅或权利记录。

## 存储、查询与恢复

使用现有 BookBuild JSONB manifest，不新增列、索引或迁移，无依赖变化。新收据查询按由工作区所属修订推导的工件 ID 参数化过滤，按工件、采集时刻、ID 排序。真实 PostgreSQL 夹具 EXPLAIN 使用现有 `idx_textbook_runtime_evidence_artifact` 索引加 Sort；没有增加写放大。构建会存储收据副本，因此多次新构建会增加 JSONB 存储量，避免将无关工件或学习者记录装入快照。

回退到先前 core/export 镜像后，新字段仍可由旧外层 v1 读取，但旧 exporter 只会给 unavailable 摘要、旧代码预检会恢复动态查询；回退不是等价验收。完整快照仍留在数据库中，升级回来后恢复使用。不得删除或回填旧构建来简化恢复。

本次 exporter handler 接近 500 行，新增业务判断放在独立 `book_verification.go` 和共享纯合同中，handler 只接线与错误响应。没有扩展其其它职责。

该快照只证明声明命令覆盖的运行行为，不证明全新安装流程、未执行的主函数输出、学习者掌握或出版权利。整书质量报告快照、权利清单和真实学习证据仍是独立要求。
