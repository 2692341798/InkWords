# 教学工件的独立验证尝试

2026-09-10，已实施并在本地部署，合同 `inkwords.verification-attempt.v1`。

每次显式重新验证创建新的 JobTask；原任务、取消记录和运行证据保留。请求包含稳定 UUID `request_id` 与当前任务 `expected_previous_task_id`，服务器解析冻结工件，不接受路径、命令或环境。精确重试返回同一任务；旧前序、改写相同请求身份或上一执行尚未退出时拒绝。

core 维护按工件串行的尝试序列，关系、序号、前次任务和执行器领取/释放信息使用列。状态为 cancelled 只是取消请求已成立；领取过执行的任务必须另有退出确认，才允许新尝试。worker 在原子领取后执行，所有退出路径均以本次领取令牌释放；取消查询失败会停止执行。进程崩溃留下的未释放领取不自动推断为已退出，必须凭实际运行环境证据恢复。

迁移将已有工件任务保留为第 1 次。原 succeeded/failed 的已结束执行保留其终态来源；旧 cancelled 且执行过的任务不补造退出记录。操作员如确认旧容器已退役、进程已退出，可以单独记录有来源的退出确认，不能把取消请求时间冒充实际退出时间。

GET 恢复最新尝试及历史，不启动工作。成功但证据过期、失败或已取消且退出确认齐全后，页面允许显式新尝试；旧式空 POST 只返回已有尝试，不能无意重启。新版尝试禁止通过旧 retry 接口清空历史。POST 精确重放可能返回历史任务，因此不在该响应中宣布下一次准入；只有最新 GET 给出 `can_start_new`。

迁移 38 增加按工件锁定的序列表、任务前序/序号、执行器领取与释放列和唯一索引。创建者只锁序列表，不反向锁稿件；worker 原子领取任务，证据提交仍沿用任务锁与原子终态。取消后先等待执行器及观察器退出，再通过不继承工作取消的 5 秒上下文写释放回执。重复释放保留首次时间。领取未释放或状态非终态时拒绝下一次尝试，不自动推断崩溃进程已退出。

持久化成功但 broker 回应丢失时，用户显式重提同一 request_id 可以再次发布尚未领取的 queued 任务；重复消息无法再次领取运行。GET 和页面刷新均不发布。旧任务及旧 API 字段仍保留；未升级的 producer 不应继续写 teaching verification，数据库形状约束拒绝无版本尝试。

迁移前保存完整 core dump，实际校验备份目录；本轮是追加式迁移，没有恢复覆盖生产数据。Down 在存在任何验证序列时拒绝丢弃退出证据，回退应保留 schema 38 并使用兼容二进制，或在另行批准后从已验证备份恢复。

已完成 PostgreSQL 迁移保真/并发领取、真实浏览器取消与重跑、精确重放/旧前序拒绝，以及新收据与原稿不变核对。实际第 2/4 次成功、第 3 次取消，分别保留独立任务；第 1 次旧取消的退出确认标记为 `operator_observed_exit`，未伪装成 worker 回执。详见 [验收记录](../qa/teaching-verification-attempts-2026-09-10.md)。
