# 本地教材资料的保存与解析边界

## 决定

本地教材资料以 SHA-256 内容寻址的 artifact 保存；任务、消息队列和模型上下文只携带 `sha256:` token、大小和来源元数据。浏览器以 multipart 流式上传，core-api 可写入 artifact，parser-service 只读共享目录。

## 资源边界

- 一个原始 PDF、DOCX、Markdown、TXT 或 ZIP 文件最多 888 MiB；超过时导入失败。
- parser-service 在校验大小和 SHA-256 的同时将 artifact 流式落到临时文件，再将 seekable 文件交给格式解析器，不把原始文件整体载入堆内存。
- ZIP 的压缩容器也落盘读取；仍限制条目数、单条解压大小、总解压大小与压缩比。嵌套 ZIP、加密条目、符号链接和路径穿越均拒绝。
- Markdown、TXT 与可引用 PDF 必须生成完整的内存结构和稳定定位，因此其可索引文本上限为 64 MiB。超过该阈值不截断、不生成部分证据：原始 artifact 保留，导入明确提示用户拆分资料后重试。
- DOCX 虽可接收 888 MiB 容器，但 `word/document.xml` 的安全解压上限仍为 16 MiB。

## 原因

产品需要保留大资料以便本地管理，但把接收上限当作内存预算会使解析 worker 易于被单个文件耗尽。分开定义原始保存边界、格式解压边界和可索引内容边界，既不悄悄丢失用户资料，也不产生不可审计的半截教材证据。
