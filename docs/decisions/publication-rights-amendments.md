# 出版权利证据补证与字体追溯

日期：2026-09-10。状态：追加补证、历史导出、受限字体来源与同构建字体权利联验已部署；正文/代码权利及其它整书验收继续。

## 已确认的问题

当前 `RightsItem` 为不可变单条记录，数据库唯一约束是 `(build_id, subject_ref)`。
`AddRightsItem` 只接受完全相同的幂等重试；pending/blocked 不能补证成 ready。
界面建议重新冻结，但内容、合同、工件和证据均不变时，`CreateBookBuild` 根据 input_hash
返回原构建。用户如实登记待核对事项后，缺少只追加、不改稿的补证路径。

当前主构建的必需权利对象只有正文与代码，导出使用字体而没有字体版本/文件 hash 的冻结记录。
实际 PDF 含 213 个未命名 Type3 字体对象；CSS 声明或当前容器安装字体只能说明候选来源，
不能代替历史 PDF 的逐字体来源证明。

## 后续实现约束

1. 保留现有 RightsItem 原件，新增版本化、只追加的权利补证记录，绑定 build/manifest、
   subject、原权利项和上一补证 ID。新记录必须有审阅来源、理由、证据引用及完整有效权利快照。
2. 显式补证请求使用 compare-and-swap；过期父版本、跨构建/主体、重复分叉和已晋级构建拒绝。
   完全相同请求幂等。不允许通过改原记录、删除 pending、换 subject 别名来放过门禁。
3. 界面、core 预检和 exporter 使用同一合同解析有效权利版本；原件、补证历史、有效版本及
   选择规则同时导出。未知来源/缺失或非法链继续阻断，不由“最新时间”猜测有效记录。
4. 新 schema 用可审查 goose 迁移；已有证据不能被回滚删除。默认旧数据仍按原记录判断。
5. 实际渲染增加字体使用/版本/file hash/许可标识的可追溯证据；区分渲染器安装的候选字体、
   真实使用字体和分发的字体文件。新证据绑定导出文件 hash；不倒填历史 PDF 为已核对。
6. 核对正文、代码、字体、图片/截图、商标和数据的实际分发范围。无该类素材时记录缺省范围，
   不制造虚构作品或授权。OFL 等开放许可需匹配具体字体版本，不能只凭字体族名称放行。

本决定延续不可变母稿/构建和来源明确的审阅规则，不改变出版社、权利人或真人试学所提供的事实。
先完成补证合同与 core/export 一致性，再把当前具体的待核对清单登记进构建。
